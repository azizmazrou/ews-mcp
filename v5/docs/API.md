# API reference — ews-mcp 4.5

This page specifies the exact inputs, outputs, limits, and error codes of every tool in `ews-mcp`
`v4.5.0a4`. The default registry exposes `18` / `29` / `34` tools at `read` / `draft` / `full`
(`35` with the semantic index). Both the summary table under [Tools](#tools) and the parameter
tables under [Tool reference](#tool-reference) are generated from the code registry. From `v5/`,
run `python scripts/dump_tool_table.py --write` to refresh them; CI verifies them with
`python scripts/dump_tool_table.py --check`. For environment variables see
[CONFIGURATION.md](CONFIGURATION.md), for policy design see [SAFETY.md](SAFETY.md), and for
upgrade notes see [UPGRADING.md](UPGRADING.md).

### mail-read

#### `list_folders` — read (min tier: read)

List mail folders as a depth-limited tree walk, or search the entire folder tree when `query` is given. Each row is {id, name, path, total, unread, children}; `id` is a short folder alias (f7) reusable as a `folder`/`parent` argument anywhere. Well-known folders also carry `wk` (e.g. 'f:inbox') — prefer passing that stable alias. Rows also carry the raw EWS FolderClass as `folder_class` when Exchange reports one (e.g. 'IPF.Note' for mail, 'IPF.Appointment' for calendar). Set include_empty=false to hide folders with zero items.

| parameter | type | required | description |
|---|---|---|---|
| `parent` | string | no | Start folder: well-known alias (f:inbox), folder alias (f7), path, or raw id. Default: the message-folder root. |
| `depth` | integer | no | (default `2`) |
| `include_empty` | boolean | no | (default `True`) |
| `query` | string | no | Non-empty case-insensitive substring match on folder name or full path across the whole tree (`depth` is ignored when `query` is set). |
| `fresh` | boolean | no | true forces a live Exchange read instead of the local mirror (responses are stamped source=cache\|live). (default `False`) |

#### `search_messages` — read (min tier: read)

Search mail. TWO ENGINES, mutually exclusive: pass `query` (an Exchange AQS string, e.g. 'from:alice@example.com subject:rfp hasattachment:yes') OR the structured filters (sender/subject/since/until/is_unread/has_attachments/categories/importance/flag_complete) — combining `query` with any structured filter is a validation error. `sender` is matched client-side against the fetched page's sender email/name, so total_available is unknown when it is used. Results are compact cards, newest first; their `id` values are short aliases (m12) for get_message / get_messages / get_thread / get_attachment. If an id later goes stale (items move), re-run this search for fresh ids.

| parameter | type | required | description |
|---|---|---|---|
| `query` | string | no | AQS query string — cannot be combined with the structured filters below. |
| `folder` | string | no | Folder alias (f:inbox, f:sent, f7), path, raw id, or f:all for the whole mailbox: all mail folders with their subfolders, without deleted items, junk, drafts and outbox; each hit then names its folder. (default `f:inbox`) |
| `sender` | string | no | Sender email or display-name substring, matched within each page; keep paging while next_offset is set (a page may hold fewer than `limit` items or none, and total_available is null on live searches). |
| `from_` | string | no | DEPRECATED alias of `sender` — do not combine the two. |
| `subject` | string | no | Subject substring. |
| `since` | string | no | Window start: 'today', '+Nd', YYYY-MM-DD, or ISO datetime (server timezone). |
| `until` | string | no | Window end: 'today', '+Nd', YYYY-MM-DD, or ISO datetime (server timezone). |
| `is_unread` | boolean | no |  |
| `has_attachments` | boolean | no |  |
| `categories` | array | no | Match messages carrying all listed Outlook categories; live search uses contains matching whereas the local mirror matches exact category elements. Cannot combine with `query`. |
| `importance` | string | no | Match messages by importance (high, normal, or low) on both the mirror and live lanes. Cannot combine with `query`. (one of: `high`, `normal`, `low`) |
| `recursive` | boolean | no | Search `folder` and all mail folders under it, merged newest first; each card carries `folder` and the result reports `folders_searched`. Always runs live. (default `False`) |
| `flag_complete` | boolean | no | true matches messages whose follow-up flag is marked Complete; false matches all other messages (unflagged or still-open flag). Always runs live and cannot combine with `query`. |
| `offset` | integer | no | (default `0`) |
| `limit` | integer | no | (default `20`) |

#### `get_message` — read (min tier: read)

Fetch one message by id (short alias from search results, e.g. m12; raw EWS ids also work). format='full' (default) returns recipients, the cleaned body (quoted history stripped — use get_thread for the conversation) and the attachment inventory; format='concise' returns the compact card; format='eml' writes the message MIME content exclusively under DATA_DIR/attachments (adding -2, -3, … rather than overwriting, and refusing above EWS_MAX_ATTACHMENT_MB) and returns only saved_path and size_bytes — a message exported from Sent Items may contain its Bcc header because the file is the message as the mailbox holds it. `flag_complete` is only reported when read live, i.e. with fresh=true. A not_found means the id went stale (items move) — re-run search_messages and retry with a fresh id.

| parameter | type | required | description |
|---|---|---|---|
| `id` | string | yes | Message id (m-alias or raw). |
| `format` | string | no | (one of: `full`, `concise`, `eml`; default `full`) |
| `include_html` | boolean | no | Also return the raw HTML body (rendering edge cases only — it is token-expensive). (default `False`) |
| `fresh` | boolean | no | true forces a live Exchange read instead of the local mirror (responses are stamped source=cache\|live). (default `False`) |

#### `get_messages` — read (min tier: read)

Fetch up to 20 messages by id in one call, preserving the requested order. Returns the canonical envelope {items, count, total_available, next_offset} plus `failed` ({id, index, code, error}) for per-message failures without aborting the remaining ids; when some items come from the local mirror and some live, top-level `source` is 'mixed' and each item carries its own `source` (plus `as_of` on mirror items). format='full' (default) returns the same cleaned message shape as get_message without downloading attachment bytes: PKCS#7 S/MIME attachments are reported as smime_type='candidate' from name and MIME type only, whereas get_message gives the confirmed 'signed'/'enveloped' classification for one message. format='concise' returns compact cards.

| parameter | type | required | description |
|---|---|---|---|
| `ids` | array | yes | Message ids (m-aliases or raw EWS ids), 1 to 20 per call. |
| `format` | string | no | (one of: `concise`, `full`; default `full`) |
| `fresh` | boolean | no | true forces a live Exchange read instead of the local mirror (responses are stamped source=cache\|live). (default `False`) |

#### `get_thread` — read (min tier: read)

Rebuild the conversation containing the given message id: Inbox and Sent are merged and sorted chronologically, each entry's body cleaned to its latest-reply-only text. Returns thread_id (t-alias), participants with message counts, and the most recent `limit` entries. Entry ids are m-aliases usable with get_message/get_attachment. Stale id → re-run search_messages.

| parameter | type | required | description |
|---|---|---|---|
| `id` | string | yes | Any message id in the thread (m-alias or raw). |
| `limit` | integer | no | (default `20`) |
| `offset` | integer | no | History paging: 0 = the most recent entries; pass the returned next_offset for older ones. (default `0`) |
| `fresh` | boolean | no | true forces a live Exchange read instead of the local mirror (responses are stamped source=cache\|live). (default `False`) |

#### `get_attachment` — read (min tier: read)

Read one attachment of a message. mode='info' → metadata only; 'text' → extracted text in memory (up to 20000 chars from `offset`, with `total_chars`, `next_offset` when more follows, `extracted_from`, and `pages`/`slides`/`sheets` count) for PDF (.pdf, requires ews-mcp[extract]), Word (.docx/.docm), Excel (.xlsx/.xlsm), PowerPoint (.pptx/.pptm), RFC-822 (.eml), attached Exchange messages, HTML (.html/.htm), and plain text (.txt/.csv/.md/.log/.json or text/*; .msg is not supported); 'save' → write the bytes exclusively under DATA_DIR/attachments (adding -2, -3, … rather than overwriting) and return saved_path; 'auto' (default) → text for every supported document/text type, otherwise info plus a hint. An smime.p7m attachment (application/pkcs7-mime) is sniffed and reported as `smime_type: signed|enveloped` — signed is NOT encrypted (auto decodes as text, cert/signature bytes show as replacement chars); enveloped IS encrypted (auto stays info; content is unrecoverable without the recipient's private key). When the message has several attachments you MUST pick one via `attachment` (a file name, a zero-based index as a string, or the `id` returned by the draft tools).

| parameter | type | required | description |
|---|---|---|---|
| `message_id` | string | yes | Message id (m-alias or raw). |
| `attachment` | string | no | Attachment file name, zero-based index as a string (e.g. '0'), or `id` returned by the draft tools (e.g. 'a1'). Optional only when the message has exactly one attachment. |
| `mode` | string | no | (one of: `auto`, `info`, `text`, `save`; default `auto`) |
| `offset` | integer | no | Character offset for reading extracted text in parts (pass the returned next_offset for the next chunk). (default `0`) |

| parameter | type | required | description |
|---|---|---|---|
| `horizon_days` | integer | no | (default `1`) |
| `fresh` | boolean | no | true forces a live Exchange read instead of the local mirror (responses are stamped source=cache\|live). (default `False`) |

#### `create_event` — write (min tier: draft)

## The canonical envelope

Every list-shaped tool returns the same paged JSON envelope so callers can page and check freshness
uniformly. Always page forward using `next_offset` until it is `null`; do not assume
`total_available` is set, because live queries return `null` whenever counting would scan the
folder on Exchange.

| field | type | meaning |
|---|---|---|
| `ok` | `boolean` | Always `true` on success (`false` only in error envelopes). |
| `items` | `array` | Page of cards or records (`search_messages` newest first; `get_messages` in caller `ids` order; `get_thread` chronological within the returned window). |
| `count` | `integer` | `len(items)` on this page. |
| `total_available` | `integer \| null` | Exact total when cheap to compute; `null` when counting would scan Exchange. |
| `next_offset` | `integer \| null` | `offset` to pass for the next page, or `null` when no more items follow. Live paths prove another page exists with a one-item lookahead (`limit + 1`), never an Exchange `count()` scan. On `get_thread`, `offset=0` returns the newest `limit` entries and `next_offset` steps backwards to older ones. |
| `source` | `"cache" \| "live" \| "mixed"` | Origin of the returned page (`"cache"`, `"live"`, or `"mixed"` on `get_messages`); pass `fresh: true` to force `"live"`. |
| `as_of` | `string` (ISO-8601 UTC) | Included when `source` is `"cache"` (and on mirror items inside a `"mixed"` `get_messages` result); records the folder's sync watermark. |
| `failed` | `array` (`get_messages` only) | Per-id failures `[{id, index, code, error}]` that did not abort the remaining `ids`. |

#### `source`

- Present on mirror-aware tools and `list_rules`.
- `"cache"` comes from the local SQLite mirror; `"live"` comes from Exchange; `"mixed"` appears only on `get_messages` when some items came from the mirror and others live.
- Inside a `"mixed"` result, each item in `items` carries its own `source`, plus `as_of` on mirror rows.
- Pass `fresh: true` to force `"live"`.

#### `failed`

- Each `[{id, index, code, error}]` entry carries the caller's `id` verbatim, its zero-based `index` in `ids`, the error `code`, and `error` capped at `300` characters (`MAX_ERROR_MESSAGE_CHARS`).
- Connection-wide errors (`auth_failed`, `throttled`, `upstream_unavailable`) still fail the whole call.

When `total_available` is exact versus `null`:

| `total_available` | cases |
|---|---|
| Exact integer | Local mirror SQLite reads (`COUNT(*)`), unfiltered single-folder live `search_messages`, bounded `list_events`, and full-list tools. |
| `null` | Live filtered or multi-folder `search_messages` where counting would scan Exchange, `search_messages(mode="semantic")`, and unbounded `list_events`. |

#### Exact integer

- Local mirror SQLite reads (`COUNT(*)`), except `search_messages(mode="semantic")`.
- Unfiltered single-folder live `search_messages` without `sender` (reads refreshed `folder.total_count`).
- Single-folder live `search_messages` filtered by `categories` or `flag_complete=true` with neither `query` nor `sender`.
- `list_folders`, `get_messages`, `get_thread`, `find_people`, and `list_rules`.
- `list_events` when all occurrences fit inside `offset + limit`.

#### `null`

- Any live `search_messages` with `sender` (or deprecated `from_`).
- Single-folder live `search_messages(flag_complete=false)`, live `importance`-filtered searches, and other live filtered searches (`query`, `subject`, `since`, `until`, `is_unread`, `has_attachments`) unless `categories` or `flag_complete=true` is also set without `query` or `sender`.

## Ids

Raw Exchange `ItemId` values are roughly 100–150 characters of base64 and change whenever an item
moves between folders. Every tool output replaces them with short aliases stored in
`DATA_DIR/memory/aliases.db`, and every id parameter accepts either an alias or a raw EWS id.
Remember one rule: if an item moved or disappeared outside `move_messages`, re-run the search or
list tool (such as `search_messages` or `list_rules`) to obtain fresh ids.

| prefix | kind | minted by | accepted by | behaviour |
|---|---|---|---|---|
| `m` | message (`m1`, `m12`) | `search_messages`, `check_messages`, `get_message`, `get_messages`, `get_thread`, `get_mailbox_overview`, `waiting_on`, `find_similar`, `move_messages` | `get_message`, `get_messages`, `get_thread`, `get_attachment`, `find_similar`, `create_draft(reply_to=…)`, `add_draft_attachment(message_id=…)`, `update_messages`, `move_messages`, `delete_messages` | `move_messages` rebinds the existing `m`-alias to the new raw EWS id so the same handle keeps working (if Exchange returns no new id on move, a `note` advises re-searching). |
| `d` | draft (`d1`) | `create_draft`, `update_draft`, `add_draft_attachment` | `update_draft`, `add_draft_attachment`, `delete_draft`, `send_draft` | Those four tools verify that the item currently lives in `f:drafts`. |
| `a` | draft attachment (`a1`) | `create_draft`, `add_draft_attachment`, `update_draft` | `update_draft(remove_attachments=…)`, `get_attachment(attachment=…)` | Resolved after case-insensitive file name and before raw attachment id or zero-based index; rejects `a` ids issued for another message. |
| `e` | calendar event (`e1`) | `list_events`, `get_mailbox_overview`, `create_event` | `get_event`, `update_event`, `respond_to_event`, `cancel_event` | `list_events` mints occurrence ids for recurring series; `update_event(scope="series")` resolves the series master. |
| `t` | thread (`t1`) | `search_messages`, `get_message`, `get_messages`, `get_thread`, `waiting_on` | Display / correlation handle (`get_thread` takes any `m`-alias in the conversation as `id`) | Bound to Exchange `conversation_id`. |
| `p` | person (`p1`) | `find_people`, `get_contact` | `get_contact` (also accepts a raw contact id or plain email address) | GAL rows bind `p` to the SMTP address; personal contacts bind `p` to the contact item id (both tools return `department` and `office` where known). |
| `k` | task (`k1`) | `list_tasks` | `update_task` | Bound to the Exchange task `ItemId`. |
| `f` | folder (`f7`, `f:inbox`, …) | `list_folders`, rule target fallback | `list_folders(parent=…)`, `search_messages(folder=…)`, `check_messages(folder=…)`, `move_messages(to_folder=…)`, `save_rule` (`move_to_folder`, `copy_to_folder`) | Accepts `f` aliases, stable `f:` well-known names, bare names like `inbox`, and paths like `Archive/2026`; `f:all` is only for `search_messages(folder="f:all")`. |
| `r` | Inbox rule (`r1`) | `list_rules`, `save_rule` | `save_rule(rule_id=…)`, `delete_rule(rule_id=…)` | Never minted for nonexistent rule ids. |

#### `a`

- `get_message` lists attachments by zero-based `idx` and `name`.
- `get_attachment` evaluates `attachment` in order: case-insensitive file name (always wins), `a<digits>` id from the draft tools, raw Exchange attachment id, then zero-based digit index (including `a<digits>` when no such alias id exists).
- An `a<digits>` id resolves to the attachment it was issued for; if issued for another message's attachment it fails with `not_found` and is never read as an index unless the local alias store (`aliases.db`) cannot be read.

#### `f`

- Stable well-known aliases: `f:inbox`, `f:sent` (`f:sentitems`), `f:drafts`, `f:trash` (`f:deleteditems`), `f:junk` (`f:junkemail`), `f:outbox`, `f:calendar`, `f:contacts`, and `f:tasks`.
- Bare names like `inbox` and paths like `Archive/2026` also work; `f:all` works only on `search_messages(folder="f:all")`.

How resolution failures surface:

- **Raw pass-through**: Any input string that does not match the alias pattern `^[a-z]{1,2}[0-9]+$`
  (aside from `f:` folder names) passes through unchanged as a raw EWS id. If `aliases.db` cannot
  be opened at startup, `NullAliaser` degrades cleanly to raw EWS ids; in `get_attachment`, an `a`
  attachment id then falls back to being read as a zero-based index.
- **Known alias whose Exchange item moved or was deleted**: Exchange raises `ErrorItemNotFound` or
  `ErrorInvalidId`, which maps to `not_found` (`404`) with a hint to re-search.
- **Unknown alias** (matches `^[a-z]{1,2}[0-9]+$` such as `m424242`, not present in `aliases.db`):
  rejected locally before calling Exchange with `validation` (`400`) and a re-search message on
  single-item tools. Two exceptions return `not_found` (`404`): `get_messages` records unknown
  `m`-aliases in `failed` with `code: "not_found"` (non-`m` alias prefixes get `validation`), and
  `save_rule` / `delete_rule` reject unknown `rule_id` handles with `not_found`.

## Error taxonomy

Every failed call returns `{"ok": false, "error": {"code": "…", "message": "…"}}` with optional
`hint` and `retry_after_s`, never a Python traceback. On the HTTP REST shim
`POST /api/tools/{name}`, `error.code` sets the HTTP status in the table below; HTTP request bodies
larger than `EWS_MAX_ATTACHMENT_MB * 4 // 3 + 1 MiB` return `413` and unknown HTTP routes or tool
names return `404`, both with `code: "validation"`. A tool above the server's tier is not
registered: it is absent from the tool list, and calling it returns `validation` with
`Unknown tool: <name>` (HTTP 404 over REST). Branch on `error.code` and never retry `validation`,
`auth_failed`, `tier_blocked`, `kill_switch`, or `recipient_blocked` with the same inputs.

| code | HTTP | meaning | what the caller should do |
|---|---|---|---|
| `validation` | 400 | Bad arguments, unknown or above-tier tool (`404` on REST), schema error, unknown alias, invalid or oversized input, worker limit, or forbidden rule change. | Fix the arguments, choose an available tool, or re-run search/list for a fresh alias; do not retry unchanged. |
| `auth_failed` | 401 | Missing or invalid `MCP_API_KEY` on HTTP, Exchange rejected credentials (HTTP 401), or the lockout guard (`AuthBreaker`) is open. | Stop immediately — retrying will not help and risks locking the directory account. Ask the operator to check credentials and restart the server. |
| `tier_blocked` | 403 | Second check inside the dispatcher when a tool requires a higher `EWS_CAPABILITY_TIER` than the server runs (`read` < `draft` < `full`); a client does not normally reach this check because tools above the server's tier are not registered. | Do not retry; use a lower-tier tool (such as `create_draft`) or ask the operator to raise `EWS_CAPABILITY_TIER`. |
| `kill_switch` | 403 | Any call that sends while `SEND_ENABLED=false` — `send_draft`, `respond_to_event`, `set_oof`, `create_event(send_invitations=true)`, `update_event(notify_attendees=true)`, or `cancel_event` on a meeting with attendees — refused at phase 1 before any token is issued. | Create a draft or save/update the event without sending notices, or ask the operator to set `SEND_ENABLED=true`. |
| `recipient_blocked` | 403 | Recipient in `to`, `cc`, `bcc`, or `attendees` matched `EWS_RECIPIENT_DENYLIST` or missed `EWS_RECIPIENT_ALLOWLIST`, or a stored event attendee has no address while a list is set. | Remove the blocked or unverifiable recipient, or ask the operator to update the recipient lists. |
| `not_found` | 404 | Stale raw EWS id (`ErrorItemNotFound` / `ErrorInvalidId`), missing folder/contact/attachment/rule, `a` alias issued for another message's attachment, or unknown `m`-alias in `get_messages`. | Re-run `search_messages`, `list_folders`, `list_events`, `find_people`, or `list_rules` to get fresh ids, then retry. |
| `confirm_invalid` | 409 | `confirm_token` is malformed, bad-signature, expired (`CONFIRM_TTL_SECONDS`), already consumed, or stale after arguments or target content changed. | Call again **without** `confirm_token` for a fresh preview, inspect the updated preview, and confirm with the new token. |
| `throttled` | 429 | Exchange back-off (`ErrorServerBusy` / rate limit); includes `retry_after_s` (default `60`). Counts toward the circuit-breaker failure counter (`ctx._circuit_failures`). | Wait at least `retry_after_s` seconds before retrying. |
| `rate_capped` | 429 | Confirmed sending call hit the per-process `EWS_MAX_SENDS_PER_HOUR` cap (default `10`/hour); returns `retry_after_s` and preserves `confirm_token`. | Wait `retry_after_s` seconds and retry the same call with the same `confirm_token` if it has not expired (or call without `confirm_token` for a new preview if it expired). |
| `internal` | 500 | Used only for an unwritable `DATA_DIR/attachments` folder or an unavailable document worker (`WORKER_UNAVAILABLE_ERROR_MESSAGE`). Does not count toward the circuit-breaker failure counter (`ctx._circuit_failures`). | Ask the operator to check local disk space, `DATA_DIR/attachments` permissions, or OS process limits. |
| `upstream_error` | 502 | Exchange failed the operation, all attendees failed in `check_availability`, final delete of a neutralised disabled rule failed, or an unexpected local exception reached `map_exception`. Counts as a failure toward the circuit breaker. | Inspect `message` and `hint`; retry once if transient, otherwise check mailbox state. |
| `upstream_unavailable` | 503 | Exchange still `connecting`, transport/timeout failure, open circuit breaker, or required local mirror / semantic index not ready (`retry_after_s` when applicable). | Call `get_server_status` (or `/readyz` on HTTP) and wait `retry_after_s` seconds before retrying. |

#### `validation`

- Returned for bad arguments, unknown tool names (`404` on REST, including tools above the server's `EWS_CAPABILITY_TIER`), JSON Schema errors on the REST shim, wrong types or ranges, and mutually exclusive filters.
- `to`, `cc`, `bcc`, and `attendees` must be a string or a list of strings; anything else fails with `validation` (`"invalid 'attendees': expected string or list of strings"`), with or without recipient lists.
- Also returned for an unknown alias handle, oversized or invalid HTML/attachment/archive/XML, document worker time or memory limits, a non-editable rule, or a forbidden rule target.

#### `auth_failed`

- Returned for a missing or invalid `MCP_API_KEY` (`Authorization: Bearer` or `X-API-Key`) on HTTP, Exchange credential rejection (HTTP 401), or an open `AuthBreaker` lockout guard.
- Includes `retry_after_s` during `EWS_AUTH_FAILURE_COOLDOWN_SECONDS`; omits `retry_after_s` once permanently open after `EWS_AUTH_MAX_REJECTIONS` rejections since the last successful login.

#### `recipient_blocked`

- Returned at phase 1 when an address in `to`, `cc`, `bcc`, or `attendees` (in call arguments or stored on the draft or event) matches `EWS_RECIPIENT_DENYLIST` or misses `EWS_RECIPIENT_ALLOWLIST`.
- On `update_event(notify_attendees=true)` and `cancel_event`, a stored attendee with no address at all (a name only, such as a personal distribution list) is listed under `attendees_without_address` and, when either list is set, refuses the call at phase 1 with `"cannot verify recipients: one recipient has no address that can be checked against the recipient lists"`. With no list set, the call proceeds and the preview names those attendees.
- A stored attendee or draft recipient whose value is a directory name (such as `/o=Org/ou=Group/cn=Recipients/cn=user`), or a stored draft recipient with no address on `send_draft`, is listed as stored and refused with `validation` (`invalid recipient in 'to': …`) when a list is set, never with `recipient_blocked`.

#### `confirm_invalid`

- Returned when `confirm_token` is malformed, bad-signature, expired (`CONFIRM_TTL_SECONDS`), already consumed, or stale because unhooked arguments or live target content (`send_draft`, `update_event(notify_attendees=true)`, `cancel_event`, `save_rule`, `delete_rule`) changed.
- Checked before `EWS_MAX_SENDS_PER_HOUR`.

#### `rate_capped`

- Counts confirmed calls that send — `send_draft`, `respond_to_event`, `set_oof`, invitations, update notices, and cancellations — against the per-process in-memory `EWS_MAX_SENDS_PER_HOUR` cap (default `10`/hour) and includes `retry_after_s` (at least `1`).
- Checked after token verification and already-used check, and before `confirm_token` is consumed, so a refused call keeps its token.

#### `upstream_unavailable`

- Returned when Exchange is still warming up (`connecting`), on transport/timeout errors, when the circuit breaker is open for tools that need Exchange, or when a required local mirror or semantic index is not ready (`retry_after_s` included when applicable).
- The circuit breaker opens after `CIRCUIT_FAILURE_THRESHOLD` = `5` consecutive `upstream_unavailable`, `upstream_error`, or `throttled` failures and closes after `CIRCUIT_OPEN_SECONDS` = `60` s.
- `get_server_status`, `waiting_on`, and `find_similar` do not contact Exchange and still answer while the breaker is open; while open, `get_server_status.connection` additionally holds `circuit_open: true` and `retry_after_s` (both keys are absent otherwise).

## Two-phase confirmation

Ordinary mail leaves the mailbox only through `send_draft`. Meeting mail — invitations, update
notices, responses, and cancellations — is sent by the calendar tools. Tools that send mail or
meeting mail, permanently delete messages, cancel calendar entries, change out-of-office replies,
or write Inbox rules execute in two phases. Calling without `confirm_token` changes nothing and
returns a preview plus a single-use HMAC token; repeating the call with identical arguments and
`confirm_token` executes the action.

### Confirmation sequence

1. **Phase 1 — preview**: Call the tool **without** `confirm_token`; nothing executes on Exchange.
   While `SEND_ENABLED=false`, every call that sends — `send_draft`, `respond_to_event`, `set_oof`,
   `create_event(send_invitations=true)`, `update_event(notify_attendees=true)`, and `cancel_event`
   on a meeting with attendees — is refused at phase 1 with `kill_switch` before any token is
   issued. Preview-hook tools — `send_draft`, `update_event` with `notify_attendees=true`,
   `cancel_event`, `save_rule`, and `delete_rule` — fetch and hash the live Exchange target, while
   the other two-phase tools hash the literal call arguments. Recipients in arguments and stored on
   the draft or event pass the allow/denylists at phase 1 or fail with `recipient_blocked` (or
   `validation` for a non-SMTP value such as a directory name). On
   `update_event(notify_attendees=true)` and `cancel_event`, a stored attendee with no address at
   all (a name only, such as a personal distribution list) appears in `preview` under
   `attendees_without_address`. When `EWS_RECIPIENT_ALLOWLIST` or `EWS_RECIPIENT_DENYLIST` is set,
   such an attendee refuses phase 1 with `recipient_blocked` (`"cannot verify recipients: one recipient has no address that can be checked against the recipient lists"`); with no list set, the
   call proceeds. Any address outside the
   `EWS_EMAIL` domain adds top-level `warnings: ["external recipients: …"]`.
   The response carries `requires_confirmation: true`, `preview`, `confirm_token`, `expires_at`,
   and `ttl_seconds`.
2. **Review**: Show `preview`, top-level `warnings`, and `preview.warnings` to the user or policy
   layer before proceeding.
3. **Phase 2 — execute**: Call the same tool with **identical arguments** plus `confirm_token`.
   The server re-runs the preview hook when present and verifies the HMAC signature, expiry,
   mailbox, tool name, `target_id`, and content hash, failing with `confirm_invalid` when the token
   is wrong, expired, or bound to other content. An already-used token also fails immediately with
   `confirm_invalid`. Next, for every call that sends, the server checks in-memory per-process
   `EWS_MAX_SENDS_PER_HOUR` and refuses with `rate_capped` and `retry_after_s` >= `1` when full;
   only after passing the cap is `confirm_token` consumed and the handler executed, so a
   `rate_capped` call keeps its token and succeeds once the hour has room if the token has not
   expired.

#### `send_draft`

- **When**: Always. Refused at phase 1 with `kill_switch` while `SEND_ENABLED=false`.
- **Idempotent replay**: A retry with the same `idempotency_key` within 48 h (`_IDEMPOTENCY_TTL_S = 172800`, up to `512` keys) returns `replayed: true` without sending again only when `draft_id` is the raw EWS id; a replay still counts against `EWS_MAX_SENDS_PER_HOUR`, and reusing a key for a different `draft_id` fails with `validation`. With a `d` alias the retry is treated as a new call and fails because the sent draft is no longer in Drafts.
- **Preview shows**: Fetches the draft (`f:drafts` only) and shows real `subject`, `to`, `cc`, `bcc`, `body_snippet` (first `1,000` chars of `body_text`), `attachment_count`, `attachments`, `draft_id`, `links`, `link_hosts`, and optional `warnings` / `links_unverified` (see [Draft bodies](#draft-bodies)). Every stored draft recipient is listed in `to`, `cc`, or `bcc` as stored — a name-only entry appears in the library's text form, such as `Mailbox(name='Project list')`, and a directory name appears as `/o=Org/ou=Group/cn=Recipients/cn=user`. When a recipient list is set, a non-address recipient fails with `validation` quoting that text (`invalid recipient in 'to': …`), never `recipient_blocked`.
- **Token binds**: `subject`, sorted `to`/`cc`/`bcc`, full text and HTML body, and attachments by `{name, size, id}` (not a hash of attachment bytes).
- **At phase two**: Re-fetches under the per-draft lock, re-checks the hash (any edit, `update_draft(remove_attachments=…)`, or `add_draft_attachment(message_id=…)` invalidates it), and sends that exact fetched object.

#### `cancel_event`

- **When**: Always. On a meeting with attendees (`action="cancel"`), refused at phase 1 with `kill_switch` while `SEND_ENABLED=false` and counted by `EWS_MAX_SENDS_PER_HOUR`; on an appointment without attendees (`action="delete"`), neither `SEND_ENABLED` nor the hourly cap applies.
- **Preview shows**: Makes one projected fetch and runs the fail-closed decision table below. Shows `event_id`, `subject`, `action` (`"cancel"` or `"delete"`), `attendee_count`, `attendees` (when `action="cancel"`), `attendees_without_address` (by display name when stored attendees have no address), `start`, `end`, `type`, `message` (cut to `200` chars when `action="cancel"`), and on `type="RecurringMaster"` adds `series: true`, `scope: "series"`, and a series warning `note`.
- **Token binds**: `event_id`, `action`, `subject`, `start`, `end`, `type`, `series`, `is_meeting`, `attendee_count`, sorted `attendees`, and `message`.
- **At phase two**: Re-verifies the bound hash and either cancels (`{"cancelled": true}`) or moves the plain appointment to Deleted Items with `SEND_TO_NONE` (`{"deleted": true}`, never a hard delete).

#### `create_event`

- **When**: Only when `send_invitations=true` (default `false` saves without emailing attendees and is not counted by the cap).
- **Gates**: When `true`, needs only tier `draft` and `SEND_ENABLED=true` (refused at phase 1 with `kill_switch` before any token is issued while `SEND_ENABLED=false`); `attendees` pass the recipient lists at phase 1, and phase 2 counts against `EWS_MAX_SENDS_PER_HOUR`.

#### `update_event`

- **When**: Only when `notify_attendees=true` (default `false` is a silent edit with no preview, no confirmation, and no hourly-cap count). When `true`, needs only tier `draft` and `SEND_ENABLED=true` (refused at phase 1 with `kill_switch` before any token is issued while `SEND_ENABLED=false`), checks stored attendees against the recipient lists at phase 1, and counts against `EWS_MAX_SENDS_PER_HOUR` at phase 2.
- **Preview shows**: Both preview and handler fetch the whole event through `_fetch_update_target` (resolving the series master when `scope="series"`), so both see the same event, all-day events included. `preview` holds `event_id`, current `subject`, current `start` and `end`, `type`, `scope` when given, `attendee_count`, `attendees` (addresses stored on the event: required, optional, and resources), `attendees_without_address` (by display name when stored attendees have no address), and `changes` (a new `body` appears as `body_snippet`, its first `200` chars). Stored `attendees` pass the allow/denylists at phase 1 (`recipient_blocked` when disallowed or addressless under a list, or `validation` for a directory name; nothing saved), and addresses outside the mailbox's own domain appear in `warnings`.
- **Token binds**: The event's `subject`, `location`, `start`, `end`, `type`, `attendees`, `scope`, `notify_attendees`, and every change of the call including the full `body`.
- **At phase two**: Fetches the event again via `_fetch_update_target`; if any bound value differs, it fails with `confirm_invalid` (`stale`) and saves nothing.

#### `save_rule`

- **Preview shows**: Fetches live rules and verifies target folders; `preview` shows `operation` (`"create"` or `"replace"`), planned `rule`, `outlook_only_rules`, `current` + `changes` (on replace), and `warnings`.
- **Token binds**: `rule_id`, planned `rule`, raw `target_folder_ids`, `current`, SHA-256 XML `target_fingerprint` of the replaced rule, and `outlook_only_rules` (changes to unrelated rules do not invalidate it).
- **At phase two**: Runs under in-process `_rules_lock` and re-verifies before mutating Exchange.

### Token lifetime and refusal conditions

- **Signing key**: HMAC-SHA256 over `{m: mailbox, a: action, t: target_id, c: content_hash, e: expires_at}` using `SEND_CONFIRM_SECRET` when configured, or an ephemeral per-process secret otherwise; tokens minted without `SEND_CONFIRM_SECRET` become invalid on process restart.
- **TTL**: `CONFIRM_TTL_SECONDS`, default `600` seconds.
- **Refusals (`confirm_invalid`, HTTP `409`)**:
  - `malformed` — token lacks `.` or cannot be base64/JSON-decoded.
  - `bad_signature` — HMAC signature does not match because the token was altered or the process restarted without `SEND_CONFIRM_SECRET`.
  - `expired` — current Unix timestamp exceeds `expires_at`.
  - `stale` — `mailbox`, tool name, `target_id`, or content hash differs from phase 1. Tools without a preview hook hash all call arguments; for tools with a preview hook, only `target_id` and the hook's resolved content are hashed, so an argument outside that content such as `idempotency_key` is not bound.
  - `consumed` — token was already spent on an earlier phase-2 call in this process.

- **Known limits**:
  - A confirmed sending call that its handler then refuses — for example `create_event` with `end` before `start`, which is validated only at phase 2 — still uses one slot of `EWS_MAX_SENDS_PER_HOUR` and spends its `confirm_token`.
  - `update_event` with notification runs at tier `draft` when `SEND_ENABLED=true`, while `send_draft` needs tier `full`: `EWS_CAPABILITY_TIER` does not separate "can notify attendees" from "can edit the calendar".
  - An `a` attachment id falls back to being read as a zero-based index if the local alias store (`aliases.db`) cannot be read.

### Gate order on a send call

Every dispatched call passes these gates in exact order (`ewsmcp/tools/base.py`):

| step | gate | checks | refusal code |
|---|---|---|---|
| 1 | Dispatcher vocabulary strip | Removes `confirm_token` (held for step 7) and `_verified_content_hash` so callers cannot pass or spoof internal state. | — |
| 2 | Send kill-switch | When `spec.sends_mail(kwargs)` is true (`send` class, `create_event(send_invitations=true)`, or `update_event(notify_attendees=true)`), requires `SEND_ENABLED=true` at phase 1 before connectivity or token issuance (the three notifying calendar handlers also keep a second-line check). | `kill_switch` (`403`) |
| 3 | Capability tier | Second check inside `dispatch` requiring `EWS_CAPABILITY_TIER` >= tool minimum (`read` < `draft` < `full`); tools above the server's tier are not registered and normally fail earlier with `validation` (`Unknown tool: <name>`, HTTP `404` on REST). | `tier_blocked` (`403`) |
| 4 | Upstream circuit breaker | Rejects `requires_ews=True` tools while open (`CIRCUIT_FAILURE_THRESHOLD` = `5` consecutive failures; `CIRCUIT_OPEN_SECONDS` = `60` s); local-only tools still answer. | `upstream_unavailable` (`503`) |
| 5 | Connection & lockout gate | For tools with `requires_ews=True`, rejects if `AuthBreaker` is open or Exchange is still `connecting`. | `auth_failed` (`401`) or `upstream_unavailable` (`503`) |
| 6 | Argument recipient guard | Requires `to`, `cc`, `bcc`, and `attendees` to be a string or list of strings (`"invalid 'attendees': expected string or list of strings"`), with or without lists; when `EWS_RECIPIENT_DENYLIST` or `EWS_RECIPIENT_ALLOWLIST` is set, checks them against denylist then allowlist. | `validation` (`400`) or `recipient_blocked` (`403`) |
| 7 | Two-phase confirmation, preview kill-switch, resolved recipient guard & cap reservation | Runs `preview` hook, enforces `SEND_ENABLED` and recipient lists on resolved targets, issues or verifies single-use `confirm_token`, and reserves `EWS_MAX_SENDS_PER_HOUR`. | `kill_switch` (`403`), `recipient_blocked` (`403`), `validation` (`400`), `confirm_invalid` (`409`), or `rate_capped` (`429`) |
| 8 | Unconfirmed send rate cap | When `spec.confirm_needed(kwargs)` is false and `spec.sends_mail(kwargs)` is true (an idempotent `send_draft` replay with raw EWS `draft_id`), enforces `EWS_MAX_SENDS_PER_HOUR` (`rate_capped`). | `rate_capped` (`429`) |
| 9 | Alias resolution | Resolves `id`, `message_id`, `draft_id`, `event_id`, `thread_id`, `reply_to`, and `ids` (`resolve_ids=True`). | `validation` (`400`) |
| 10 | Handler & audit log | Runs the handler on the EWS pool (re-verifying `_verified_content_hash` where bound) and appends one best-effort hash-chained audit line off the event loop. | Tool / upstream code |

#### Step 4 — Upstream circuit breaker

- For tools with `requires_ews=True`, rejects while open after `CIRCUIT_FAILURE_THRESHOLD` (`5`) consecutive `upstream_unavailable`, `upstream_error`, or `throttled` failures (`CIRCUIT_OPEN_SECONDS`, `60` s).
- `get_server_status`, `waiting_on`, and `find_similar` (`requires_ews=False`) still answer; while open, `get_server_status.connection` adds `circuit_open: true` and `retry_after_s`.

#### Step 7 — Two-phase confirmation & cap reservation

- Runs `preview` hook when present (`send_draft`, `update_event(notify_attendees=true)`, `cancel_event`, `save_rule`, `delete_rule`).
- When `spec.sends_mail(kwargs, content)` is true (including `cancel_event` with `action="cancel"`), requires `SEND_ENABLED=true` at phase 1 before issuing a token.
- Checks resolved recipients (stored draft recipients or stored event attendees) against `EWS_RECIPIENT_DENYLIST` and `EWS_RECIPIENT_ALLOWLIST` when either list is set: refuses disallowed addresses and addressless event attendees (`attendees_without_address`) with `recipient_blocked`, and refuses non-SMTP values (directory names, or addressless draft recipients on `send_draft`) with `validation`.
- Phase 1 returns `preview` + `confirm_token`.
- Phase 2 verifies `confirm_token`, rejects already-used tokens (`confirm_invalid`), reserves an in-memory per-process `EWS_MAX_SENDS_PER_HOUR` slot for sending calls (`10`/hour default, `retry_after_s` >= `1`; refusal preserves the token), and only then consumes `confirm_token`.

#### Step 10 — Handler & audit log

- Runs the handler on the EWS pool (`send_draft`, `update_event(notify_attendees=true)`, and `cancel_event` re-verify `_verified_content_hash`).
- Appends one best-effort hash-chained audit line off the event loop recording time, tool, outcome and, for calls of class `send` or `destructive`, the target ids (`draft_id`, `event_id`, `ids`), with no recipients, subjects, or bodies.

## Cache freshness contract

When the local SQLite mirror is enabled, read tools answer from `DATA_DIR/cache/mirror.db` instead
of calling Exchange on every request. The mirror accelerates reads and never blocks them: if a
folder is not mirrored, has no watermark yet, or hits a SQLite error, the tool falls back to live
Exchange automatically. Check `source` and `as_of` on every read, and pass `fresh: true` whenever
you need guaranteed real-time Exchange state.

| aspect | behaviour |
|---|---|
| Scope & defaults | Enabled by `EWS_CACHE_ENABLED` (default `True`). Syncs `EWS_CACHE_FOLDERS` (default `'inbox,sent'`) across `EWS_CACHE_WINDOW_DAYS` (default `365` days), plus folder counts, a `14`-day calendar window (`CALENDAR_WINDOW_DAYS = 14`, up to `200` items), and tasks. |
| `source: "cache"` and `as_of` | Returned when the folder is in `EWS_CACHE_FOLDERS`, has a sync watermark, and `fresh` is `false`; `as_of` is the folder's last UTC sync watermark. |
| `fresh: true` | Supported on `list_folders`, `search_messages`, `check_messages`, `get_message`, `get_messages`, `get_thread`, `get_mailbox_overview`, and `list_tasks`. Forces a live Exchange read (`source: "live"`). |
| Always-live calls | `search_messages` with `folder="f:all"`, `recursive=true`, or `flag_complete`; `get_message` with `include_html=true` or `format="eml"`; `list_events`, `get_event`, `check_availability`, `get_oof_settings`, `list_rules`, and `get_attachment` (which uses a separate 10-minute in-memory text cache). |
| Mirror vs live fields | Mirror rows strip learned signatures, omit `flag_complete`, omit attachment metadata (adding `attachments_hint`), and match exact category names. |
| Write-through & multi-process lease | Write tools patch or tombstone mirror rows best-effort; `get_server_status.cache` reports watermarks, counts, `db_mb`, and `sync.role` (`"leader"` or `"follower"`). |
| Semantic search (`EWS_SEMANTIC_INDEX`) | Enables `search_messages(mode="semantic")` (`mode: "semantic"`) and `find_similar` via `pgvector`; both require a warm mirror (`waiting_on` requires `sent` synced). |

#### `source: "cache"` and `as_of`

- Hot-folder deltas run every `EWS_CACHE_SYNC_SECONDS` (default `45` s, minimum `5` s).
- The folder tree, calendar overview window, and tasks refresh every `EWS_CACHE_HIERARCHY_SECONDS` (default `600` s).

#### Mirror vs live fields

- Mirror rows strip learned per-sender trailing signatures (`SIG_MIN_HITS = 3`) in addition to quoted history, and omit `flag_complete` (reported only when `fresh=true`).
- Mirror rows store `has_attachments` without attachment metadata; on `get_message` and `get_messages` (`format="full"`), mirror hits with attachments add `attachments_hint` advising `fresh=true` or `get_attachment`.
- On `search_messages(categories=…)`, live queries match category substrings whereas the mirror matches exact category names.

#### Write-through & multi-process lease

- `update_messages` (`set_read`, `categories`), `move_messages`, and `delete_messages` patch or tombstone mirror rows best-effort after Exchange succeeds.
- `get_server_status.cache` reports per-folder watermarks, row counts, `db_mb`, and `sync` health, including `sync.role`: `"leader"` for the process holding `cache/sync.lock` and running `SyncEngine`, or `"follower"` for extra processes reading the shared mirror without running background sync.

#### Semantic search (`EWS_SEMANTIC_INDEX`)

- `mode: "semantic"` on `search_messages` runs a hybrid FTS + vector RRF merge (degrading to keyword-only with `degraded` on vector outage) and, like `find_similar`, exists only when `EWS_SEMANTIC_INDEX` is enabled (`pgvector`) and requires a warm mirror (`waiting_on` also requires the mirror with `sent` synced).

## Searching several folders

`search_messages` offers two multi-folder modes that fan out across folders and merge hits newest
first by `datetime_received`. Both modes always query Exchange live (`source: "live"`), requesting
up to `offset + limit` items per folder so paging applies to the merged list rather than individual
folders. Keep `offset + limit <= 500`, and when `sender` is set, keep paging while `next_offset` is
non-null even if a page returns fewer than `limit` items.

| mode | folders in scope | folders excluded |
|---|---|---|
| `folder="f:all"` (`ALL_FOLDERS`) | Every `IPF.Note*` mail folder and subfolder in the mailbox. | Deleted Items (`f:trash` / `f:deleteditems`), Junk Email (`f:junk` / `f:junkemail`), Drafts (`f:drafts`), Outbox (`f:outbox`), and all subfolders beneath them. |
| `recursive=true` (with `folder=<target>`) | The target `folder` and all `IPF.Note*` subfolders beneath it. | Non-`IPF.Note*` folders. When `folder` explicitly names Deleted Items, Junk, Drafts, or Outbox with `recursive=true`, that subtree **is** searched. |

Limits, failure rules, and multi-folder response fields:

| rule / field | behaviour |
|---|---|
| Folder cap (`MAX_FANOUT_FOLDERS`) | Queries at most `200` folders per call; additional folders are omitted and counted in `folders_skipped` (included when non-zero). |
| Window cap (`MAX_FANOUT_WINDOW`) | Requires `offset + limit <= 500` (`limit` is `1..50`); exceeding `500` fails with `validation`. |
| Per-card `folder` | Every returned message card includes `folder` set to its folder path (such as `"Inbox"` or `"Archive/2026"`). |
| `folders_searched` & `folders_failed` | `folders_searched` counts folders that answered; `folders_failed` lists paths of folders that raised a non-throttling error (included when non-empty). If **every** folder fails, the call fails with the first error. |
| Throttling | If Exchange throttles **any** folder, the entire call fails immediately with `throttled` (`429`, `retry_after_s`). |
| `sender` post-filter | `sender` (and deprecated `from_`) filters each merged `offset..offset + limit` slice, so keep paging while `next_offset` is non-null even on a short or empty page. |
| Single-folder tools | `check_messages` rejects `folder="f:all"`, `recursive=true`, and `/*` folder patterns with `validation`. |

#### `sender` post-filter

- Because `sender` (and deprecated `from_`) is matched within each merged `offset..offset + limit` slice, a page can hold fewer than `limit` cards (or `0`) while older matches remain; keep paging while `next_offset` is non-null.
- `total_available` is `null` whenever any folder has matches past `offset + limit`, `folders_failed` is non-empty, `folders_skipped` is non-zero, or `sender` is set.

## Draft attachments

`create_draft` attaches files when creating a draft, `add_draft_attachment` adds one file or
existing mail message (`message_id`), and `update_draft(remove_attachments=[…])` detaches
attachments by name or id. `update_draft`, `add_draft_attachment`, `delete_draft`,
and `send_draft` only accept items currently in `f:drafts`; anything else fails with `validation`.
Every attachment change alters the draft's bound state, so any earlier `send_draft` `confirm_token`
is refused with `confirm_invalid`.

### Adding files or messages (`create_draft`, `add_draft_attachment`)

Each attachment supplies **exactly one** source (combining or omitting sources fails with
`validation`):

| source | accepted on | rules and limits |
|---|---|---|
| `content_base64` | `create_draft`, `add_draft_attachment` | Base64-encoded file bytes (`filename` required; `content_type` optional, guessed from `filename` or `"application/octet-stream"`). Invalid base64 or `0`-byte content fails with `validation`. |
| `path` | `create_draft`, `add_draft_attachment` | Relative path inside `EWS_ATTACHMENT_DIR` (`filename` defaults to the file's basename). Fails with `validation` when `EWS_ATTACHMENT_DIR` is unset, or when the path is absolute, uses `..`, resolves via symlink outside `EWS_ATTACHMENT_DIR`, is not a regular file, or is empty (`0` bytes). |
| `message_id` | `add_draft_attachment` only | Attaches an existing mail message's `mime_content` as a `message/rfc822` `.eml` file after item-class, size, `Bcc` stripping, and filename sanitisation checks. |

#### `message_id`

- `content_type` must be omitted or `"message/rfc822"`.
- Refuses non-mail items (`item_class` outside `IPM.Note*`, calendar/contact/task items, `BEGIN:VCALENDAR` / `BEGIN:VCARD` MIME) and refuses attaching the draft to itself (`validation`).
- Checks declared `size` against `EWS_MAX_ATTACHMENT_MB` **before** downloading `mime_content` and checks byte length again after download.
- Strips top-level `Bcc` and `Resent-Bcc` headers (folded continuation lines included) from the attached copy.
- Builds the `.eml` name from `filename` or the source `subject`: strips format/control/surrogate characters (`Cc`, `Cf`, `Cs` — bidi marks, zero-width chars, C0/C1 controls), replaces line-break controls with spaces and unsafe path characters with `_`, and prefixes `_` onto reserved Windows device stems (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`).
- Caps the stem at `120` characters (`_MAX_EML_STEM_CHARS`) and `200` UTF-8 bytes (`_MAX_EML_STEM_BYTES`) before `.eml` (`message.eml` fallback).

Caps, returned fields, and token binding:

- **Per-call caps**: `create_draft` accepts at most `20` attachments (`MAX_ATTACHMENTS = 20`);
  total attachment bytes per call may not exceed `EWS_MAX_ATTACHMENT_MB` (default `25` MB, range
  `1..50`). If an Exchange attach call fails after `create_draft` saves the draft, the draft stays
  in `f:drafts` and `attachments_failed` (`[{name, error}]`) names what failed.
- **Returned ids and `send_draft` binding**: Returned attachment entries (`attachments` and `added`)
  carry `{name, size, id}`, where `id` is a short `a`-alias (`a1`, `a2`, …). On `send_draft`, each
  attachment is bound into `confirm_token` by `name`, `size`, and `id` (not by a hash of its byte
  content).

### Removing attachments (`update_draft(remove_attachments=[…])`)

| stage | behaviour |
|---|---|
| Selector matching (all-or-nothing) | Matches every `remove_attachments` name or id under `_draft_lock` before any Exchange write; an unmatched or ambiguous selector fails with `validation` without modifying the draft. |
| Execution order & partial failure | Detaches matched attachments **before** saving other draft fields; a partial removal failure reports `removed` and remaining `attachments`. |

#### Selector matching (all-or-nothing)

- Runs under the per-draft lock (`_draft_lock`) before any Exchange write and requires the item to be in `f:drafts`.
- Each entry in `remove_attachments` is an attachment name (exact match first, then case-insensitive) or attachment id (`a`-alias or raw EWS attachment id).
- An unmatched entry fails with `validation` naming the selector (cut to `80` characters, `_MAX_ECHO_SELECTOR_CHARS`) without modifying the draft; a name matching more than one attachment fails with `validation` listing the `a`-alias ids to choose from.

#### Execution order & partial failure

- Detaches matched attachments **before** saving `to`, `cc`, `bcc`, `subject`, or `body`, deleting one attachment per server call.
- If a multi-attachment removal fails after earlier removals succeeded, no other draft field has changed and the error carries `removed` (already deleted) and `attachments` (remaining on the draft) so the caller can retry from the real state; on full success, `update_draft` returns the remaining `attachments`.

## Draft bodies

`create_draft` and `update_draft` accept `body_format="text"` (the default) or `body_format="html"`
(for formatted or right-to-left mail; calendar event bodies remain plain text only).
Plain text is HTML-escaped with `<p>` per blank-line paragraph and `<br/>` for single line breaks;
HTML is tokenised in one linear-time pass off the event loop (`ewsmcp.htmlsafe.sanitise_html`,
custom stdlib-only tokenizer, never `html.parser`) and rebuilt from an allow-list as
`<html><body…>…</body></html>` to a fixed point. Remember that `update_draft` requires `body`
whenever `body_format="html"`, and `send_draft` inspects every link and destination host in the
stored draft during phase 1.

### Elements (`sanitise_html`)

| category | elements / constructs | what happens |
|---|---|---|
| Document wrappers (`WRAPPER_ELEMENTS`) | `html`, `body` | Safe global attributes (`dir`, `lang`, `align`, `style`) on the first `<html>` and first `<body>` merge onto the single output `<body>`, with `<body>` winning; attributes on duplicate `<html>`/`<body>` tags increment `removed_attributes`. |
| Allowed elements (`ALLOWED_ELEMENTS`) | `p`, `br`, `div`, `span`, `b`, `strong`, `i`, `em`, `u`, `s`, `strike`, `sub`, `sup`, `ul`, `ol`, `li`, `table`, `thead`, `tbody`, `tfoot`, `tr`, `td`, `th`, `caption`, `colgroup`, `col`, `h1`–`h6`, `blockquote`, `pre`, `code`, `hr`, `a`, `font` | Re-serialised with escaped text and attributes, browser-matching implied end tags, and table normalization; only `br`, `hr`, `col` (`VOID_ELEMENTS`) are void. |
| Empty or nested anchors | `<a>` with no visible text in any descendant (table cells included), or an outer `<a>` wrapping a nested `<a>` across a table cell | Unwrapped (preserving inner content) and counted in `removed_links`. |
| Dropped elements (`DROP_CONTENT_ELEMENTS`) | `33` active, head, form, media, embedded, and image tags (`script`, `style`, `head`, `iframe`, `form`, `svg`, `math`, `img`, … — full list below) | Dropped completely — non-void containers together with their contents — and recorded in `removed_elements`. |
| Other unknown tags | Any tag not listed above (including `xmp` and `plaintext`) | Unwrapped keeping its text and allowed children; tag name recorded in `removed_elements`. `xmp` and `plaintext` use HTML5 raw-text scanning (`</xmp>` or to end of input) and keep their content as literal text. |
| Non-element markup & control chars | Comments, marked sections, CDATA, processing instructions, doctypes, NUL/illegal XML C0 controls, surrogates, `U+FFFE`/`U+FFFF`, and bidi overrides `U+202D` / `U+202E` | Stripped silently. Runs of more than `30` combining marks (`MAX_COMBINING_RUN`) are cut to `30`. |

#### Allowed elements (`ALLOWED_ELEMENTS`)

- Every text node and attribute value is escaped on re-serialisation; only `br`, `hr`, `col` (`VOID_ELEMENTS`) are void, and trailing `/` on non-void HTML tags is ignored.
- Implied end tags close `<p>`, `<h1>`–`<h6>`, `<li>`, `<a>`, and table sections/rows/cells the way browsers and libxml2 do.
- Table sub-elements (`<td>`, `<tr>`, …) outside `<table>` lose only their tags while keeping their text and allowed children (tag recorded in `removed_elements`), and bare flow content inside `<table>`/`<tr>` opens implicit `<tr><td>`.

#### Dropped elements (`DROP_CONTENT_ELEMENTS`)

- Full tag list: `script`, `style`, `head`, `title`, `meta`, `link`, `base`, `object`, `embed`, `iframe`, `frame`, `frameset`, `applet`, `noembed`, `noframes`, `form`, `input`, `button`, `select`, `option`, `textarea`, `svg`, `math`, `template`, `noscript`, `audio`, `video`, `source`, `track`, `canvas`, `map`, `area`, `img` (`img` is excluded so remote URLs cannot act as a tracking or exfiltration channel).
- Non-void containers are dropped together with their contents and recorded in `removed_elements`.
- `script`, `style`, `title`, `textarea`, `noembed`, `noframes`, and `iframe` use HTML5 raw-text scanning; omitted `</head>` closes automatically at `<body>`, the first non-head element, or non-whitespace text.

### Attributes and links (`sanitise_html`)

Numeric character references in attribute values decode with or without `;`, whereas named character
references in attributes decode **only** when terminated with `;` so query parameters like `&copy=1`
stay verbatim. All `on*` event handlers, duplicate attributes on one tag, and unlisted attributes
are dropped and counted in `removed_attributes`, except a duplicate invalid `href` on `<a>`, which
counts in `removed_links`:

| element(s) | allowed attributes and values | link / attribute removal rules |
|---|---|---|
| All allowed elements & `body` (`GLOBAL_ATTRS`) | `dir` (`ltr\|rtl\|auto`), `lang` (BCP-47 tag `<= 35` chars), `align` (`left\|right\|center\|justify`), `style` (see next table) | Invalid values increment `removed_attributes`. |
| `a` (`a[href]`, `title`) | `href`: `http://`, `https://`, or single-address `mailto:` (`<= 2,048` chars, `MAX_HREF_CHARS`); `title`: `<= 1,000` chars (`MAX_TITLE_CHARS`; tab, CR, and LF are accepted, other control chars and bidi overrides are rejected) | Checks scheme after decoding references and stripping whitespace/controls; invalid URLs strip `href` (keeping link text) and increment `removed_links`. |
| `td`, `th` | `colspan` (`0..1000`), `rowspan` (`0..1000`), `width`, `height` (number with optional `px` or `%`) | Invalid values increment `removed_attributes`. |
| `table` | `border`, `cellpadding`, `cellspacing` (`0..1000`), `width` (number with optional `px` or `%`) | Invalid values increment `removed_attributes`. |
| `col` | `span` (`1..1000`), `width` (number with optional `px` or `%`) | Invalid values increment `removed_attributes`. |
| `ol` | `start` (signed integer), `type` (`1\|a\|A\|i\|I`) | Invalid values increment `removed_attributes`. |
| `font` | `face` (safe font list `<= 200` chars), `size` (`1`–`7`, `+1`–`+7`, `-1`–`-7`), `color` (`#rgb`, `#rrggbb`, or 2–30 ASCII letters) | Invalid values increment `removed_attributes`. |

#### `a` (`a[href]`, `title`)

- Scheme is checked after decoding character references and stripping whitespace and control characters.
- Non-`http`/`https`/`mailto` schemes, `@` userinfo or `\` before `?`/`#`, invalid IDNA/IP hosts or hosts `> 253` chars, and unparseable `href` values strip `href` while keeping link text and increment `removed_links`.
- On `mailto:`, query/fragment parts and extra recipients are stripped and counted in `removed_links`.

### `style` declarations (`ALLOWED_STYLE_PROPERTIES`)

`style` normalises internal whitespace, splits `;`-separated declarations, and increments
`removed_attributes` once if any declaration in the attribute is dropped (omitting `style` altogether
when no declaration survives):

| rule | allowed | dropped |
|---|---|---|
| Typography & bidi | `direction`, `unicode-bidi` (`normal\|embed\|isolate\|plaintext` only), `text-align`, `vertical-align`, `line-height`, `white-space`, `font-family`, `font-size`, `font-weight`, `font-style`, `text-decoration` | Any other `unicode-bidi` value; `font-size` of `0` or below `6px` / `6pt` / `6` (unitless) / `0.375em` / `0.375rem` / `37.5%`, or outside `ALLOWED_FONT_SIZE_KEYWORDS` (`xx-small`..`xxx-large`, `smaller`, `larger`, `inherit`, `initial`). |
| Colour, spacing, border, size, list | `color`, `background-color`, `margin` (`-top`/`-right`/`-bottom`/`-left`), `padding` (`-top`/`-right`/`-bottom`/`-left`), `border` (`-top`/`-right`/`-bottom`/`-left`, plus `-width`/`-style`/`-color` and `border-collapse`), `width`, `height`, `list-style-type` | Positioning, layout offsets, `display`/`visibility`/`opacity`, background images, custom properties, and any unlisted property. |
| Value characters & tokens | `1..200` chars (`MAX_STYLE_VALUE_CHARS`), balanced quotes and parentheses, composed solely of letters (including non-Latin font names), digits, spaces, and `# % . , ( ) ' " - + !` | Values `> 200` chars; values containing `@`, `\`, `<`, `>`, or `/*`; values containing `url(`, `expression`, `javascript`, `vbscript`, `behavior`, or `-moz-binding`. |

### HTML limits, refusals, and `sanitised` reporting

| limit / check | constant | value | behaviour |
|---|---|---|---|
| Input HTML size | `MAX_HTML_CHARS` | `200,000` chars | Measured on the input string (escaped output may be longer); above `200,000` fails with `validation` before saving. |
| Non-blank visible text | — | `>= 1` visible char | Inputs leaving no visible text after sanitising fail with `validation` before saving (blank fillers such as `U+3164` and `U+2800`, whitespace, controls, and default-ignorable code points do not count as visible). |
| Fixed-point re-sanitise | — | up to `3` passes | Output is re-sanitised to verify stability while keeping first-pass removal counts; non-converging markup fails with `validation`. |
| Combining mark run | `MAX_COMBINING_RUN` | `30` marks | Longer runs in text or `title` are cut to `30`. |
| Attribute value caps | `MAX_HREF_CHARS` / `MAX_TITLE_CHARS` / `MAX_STYLE_VALUE_CHARS` | `2,048` / `1,000` / `200` chars | Overlong values are stripped and counted in `removed_links` or `removed_attributes`. |
| Link-inspector HTML cap | `MAX_INSPECT_HTML_CHARS` | `2,000,000` chars | Stored HTML above `2,000,000` chars on `send_draft` skips tokenizer parsing, runs the raw-text host scan only, warns, and sets `links_unverified: true`. |
| Host length / truncation | `MAX_HOST_CHARS` / `TRUNCATED_HOST_CHARS` | `253` / `80` chars | `sanitise_html` drops `href`s with hosts `> 253` chars; `send_draft` preview cuts hosts `> 253` chars to `80` chars (`head…tail`) with a warning and skips IDNA. |

When `body_format="html"` succeeds on `create_draft` (or `update_draft` with `body`), the response
includes `body_format: "html"` and — **only** when at least one element, attribute/style, or link
part was stripped — `sanitised: {removed_elements, removed_attributes, removed_links}`.

### `send_draft` link preview

During phase 1 of `send_draft`, `inspect_draft_links` inspects URL-bearing attributes (`href`,
`xlink:href`, `action`, `formaction`, `src`, `srcset`, `background`, `poster`, `data`, and `cite`)
via the tokenizer up to `2,000,000` characters. It also takes the **union of destination hosts
across eight readings of the raw body text** (`http`, `https`, `ftp`, `ftps`, `ws`, `wss`, `file`,
scheme-relative `//`, and `mailto:`, without quote or markup parsing), crossing four
character-reference readings with two whitespace readings:

- **Four character-reference readings**: **none** decoded; single-pass `html.unescape` browser
  rules; multi-pass `html.unescape` for nested references; and a **3-pass** scan decoding all
  numeric and named references with or without `;`.
- **Two whitespace readings**: NUL, tab, CR, and LF **deleted**, and NUL, tab, CR, and LF
  **replaced by a space**.

| `preview` field | order, cap, and meaning |
|---|---|
| `link_hosts` | Up to `50` (`MAX_PREVIEW_HOSTS`) `{host, count[, as_written][, embedded][, unparsed]}` entries ordered from mismatching and parsed `<a>` hosts to `embedded` and `unparsed` hosts; > `50` adds `link_hosts_total` and sets `links_unverified: true`. |
| `links` | Up to `20` (`MAX_PREVIEW_LINKS`) distinct `{text, href}` pairs from parsed `<a>` elements with mismatching links listed first (`text` cut to `120` chars, `MAX_PREVIEW_LINK_TEXT_CHARS`; `unparsed` raw-scan hosts never add to `links`), plus `links_total` when more than `20` exist. |
| `warnings` | Omitted when empty. Orders critical and mismatch warnings (`<= 100`, `MAX_MISMATCH_WARNINGS`) before folded other warnings; caps the whole list at `20` lines (`MAX_PREVIEW_WARNINGS`) and sets `warnings_total` when more warnings exist than lines shown. |
| `links_unverified` | Set to `true` when the stored HTML exceeds `2,000,000` characters, when distinct `link_hosts` exceed `50`, when mismatch warnings exceed `100`, or on an internal inspection error. |

#### `link_hosts`

- Ordered as: (1) hosts of mismatching links, (2) other parsed `<a>` hosts, (3) `embedded: true` non-anchor attribute hosts, and (4) `unparsed: true` hosts found only by the raw-text union scan.
- `as_written` appears for IDN/punycode hosts, percent-encoded hosts, and trailing-dot `mailto:` domains; a trailing dot on an `http`/`https` host is stripped without `as_written`, and hosts `> 253` chars are cut to `80` chars without IDNA.
- Adds `link_hosts_total` and sets `links_unverified: true` when more than `50` distinct hosts exist.

#### `warnings`

- Ordered as: (1) unverified and size notices; (2) the singular hosts-omitted notice (`> 50` hosts) and the singular outside-normal-markup notice (`unparsed` hosts); (3) mismatch warnings, shown up to `100` (`MAX_MISMATCH_WARNINGS`) plus one count line and `links_unverified: true` beyond `100`; (4) all other warning kinds, each folded into one count line beyond `3`.
- Mismatch warnings cover mismatched URL/host/address/`https`-vs-`http`/port in link text or `title`, adjacent split-anchor claims, mixed ASCII/non-ASCII link-text tokens, and `mailto:` links with multiple recipients or query parameters.
- Other warning kinds cover empty links, numeric hosts, overlong hosts, IDN/punycode hosts, suspicious host chars, embedded userinfo, malformed URLs, non-standard schemes, non-anchor active URLs, and bidi overrides in link text.
- The list is cut at `20` lines in total (`MAX_PREVIEW_WARNINGS`, or more only when the critical lines in groups 1–3 alone exceed `20`), and non-critical warnings fill what is left; `warnings_total` is set only when more warnings were found than lines are shown.

### Promises and non-promises

Four things are promised:

1. **Sanitised bodies are exact**: Any body written through `sanitise_html` has accurate links, link
   text, and mismatch warnings because this server rebuilt its markup.
2. **Every URL host in the raw text is surfaced**: For any stored body, `link_hosts` includes the
   union of destination hosts across all eight character-reference × whitespace readings of the raw
   text (marked `unparsed: true` when outside parsed links), or `links_unverified` is `true`.
3. **Critical notices are never cut**: Unverified/size notices, the hosts-omitted notice, the
   outside-normal-markup notice, and mismatch warnings (up to `100`, plus a count line and
   `links_unverified: true` beyond `100`) always precede folded non-critical warnings and are never
   dropped.
4. **Bounded cost and GIL time**: `sanitise_html` runs in under `2` s up to `200,000` characters,
   `inspect_draft_links` runs in under `5` s up to `2,000,000` characters, and neither holds the
   Python GIL for more than `~0.2` s in a single library call.

Two things are **not** promised:

- Pairing link text with link target inside quoted or foreign HTML that this server did not write.
- Detecting look-alike characters in link text beyond removing whitespace of any kind around dots
  before matching host-like tokens and warning when a whitespace-free link-text token mixes ASCII
  letters with any non-ASCII character (pure non-Latin link text such as Arabic gets no warning).

## Reading attachments

`get_attachment` inspects attachment metadata, extracts readable text in memory, or writes raw
bytes under `DATA_DIR/attachments`. No attachment is ever executed, opened in an external helper
program, or written to disk unless you request `mode="save"`. When a message has more than one
attachment, `attachment` is required and omitting it fails with `validation`. `get_attachment`
reads `attachment` in this order:

1. **File name** matched case-insensitively; a matching file name always wins.
2. **`a<digits>` id** returned by the draft tools, resolved to the attachment it was issued for. An
   `a<digits>` id issued for an attachment of another message fails with `not_found` —
   `"Attachment id 'a7' belongs to another message's attachment. Available here: …"` — and is never
   read as an index unless the local alias store (`aliases.db`) cannot be read, in which case it
   falls back to step 4.
3. **Raw Exchange attachment id**.
4. **Zero-based index** written as digits, including `a<digits>` when no such alias id exists.

### Modes (`mode`, default `"auto"`)

| `mode` | supported document or text | unsupported binary | Outlook `.msg` (`application/vnd.ms-outlook`) |
|---|---|---|---|
| `"auto"` (default) | Extracts text (`mode: "text"`). | Returns metadata (`mode: "info"`) + `mode='save'` `hint` without downloading bytes (always identical whether or not the attachment was cached earlier). | Returns `mode: "info"` + `note` and `hint` advising `mode='save'`. |

| `"text"` | Extracts up to `20,000` chars (`_TEXT_CAP`) from `offset`. | Fails with `validation` + `hint` listing supported types. | Returns `mode: "info"` + `note` and `hint` advising `mode='save'`. |
| `"save"` | Writes raw bytes as Exchange delivers them under `DATA_DIR/attachments` and returns `saved_path` (attached Exchange items have no file bytes and fail with `validation`). | Writes bytes and returns `saved_path`. | Writes `.msg` bytes and returns `saved_path`. |

#### `"pdf"`

- Password-protected PDFs that do not open with an empty password fail with `validation`; an unreadable page yields an empty page plus a note.
- `"PDF has no text layer"` appears only when both `layout` and `plain` passes are empty across all pages.

#### `"xlsx"`

- Each worksheet renders under `--- Sheet: <name> ---` with tab-separated shared strings, inline strings, booleans, numbers, and cached formula values.
- `xl/styles.xml` formats dates/times as `YYYY-MM-DD`, `YYYY-MM-DD HH:MM[:SS]`, or `HH:MM[:SS]` (`1900` and `1904` date systems) and percentages as `%` (falls back to raw numbers with a note if `xl/styles.xml` fails).
- Worksheets exceeding the `20` MiB XML-part cap still stream their first `5,000` rows with `partial: true` and a cut note.

#### `"eml"`

- Raw 8-bit header bytes decode as UTF-8 falling back to `Windows-1256` before cutting; body parts decode via BOM or `ALLOWED_CHARSETS` (`utf-8`, `utf-16`, `windows-1256`, `windows-1252`, `iso-8859-1`, `iso-8859-6`).

#### `"text"`

- Reads only as many `UTF-8` or BOM-marked `UTF-16` bytes as `5,000,000` chars can require, with no per-line loop or line-ending normalisation, and replaces lone surrogates with `U+FFFD`.
- Never refused for leading bytes.

PDF layout, fallback, and reading-order rules (`ewsmcp.pdftext`):

| step / rule | constants | behaviour |
|---|---|---|
| Single-pass non-RTL fast path | — | Pages with no right-to-left letters and no invisible Form `/XObject` (`/Resources` -> `/XObject` with `/Subtype /Form`) return byte-identical to `pypdf` `layout` mode without a second pass. |
| Plain-mode file-order fallback | — | Runs an unpatched plain pass when layout text is empty, a Form `/XObject` is present, or RTL letters appear, replacing layout mode with a file-order note when plain recovers missing text. |
| `/ToUnicode` RTL ligatures | `MAX_BFRANGE_EXPAND = 256`, `MAX_TOUNICODE_BYTES = 2,000,000`, `MAX_CODESPACE_HEX_CHARS = 4` | Multi-letter RTL ligatures in `bfchar` and `bfrange` (expanding single start-string ranges up to `256` codes and leaving larger ranges or `> 2`-byte codespaces untouched) are rewritten to visual order in memory on the layout reader. |
| Line reading order & Arabic variants | `MAX_LINE_CHARS = 5,000`, `MAX_WORD_REPAIR_PIECES = 12`, `MAX_SPLIT_TOKEN_PIECES = 8` | Converts lines `<= 5,000` chars to reading order, normalises Arabic presentation and shared variants, and rejoins words split by layout spaces. |

#### Plain-mode file-order fallback

- Plain-mode text (from an unpatched reader when ligature maps were rewritten) is also taken when layout text is empty, a Form `/XObject` is present, or RTL letters appear.
- Plain mode replaces layout mode with a file-order note when layout text is empty and plain text is non-empty, or when plain text has at least `20` more non-space characters and more than `1.2×` as many (such as rotated text matrices, rotating `cm`, skewed OCR layers, or Form XObjects invisible to `layout` mode).

#### Line reading order & Arabic variants

- Lines up to `5,000` chars after collapsing spaces convert to reading order using Microsoft Word rules (when Producer/Creator names whole-word `Word`) or Unicode rules; longer lines stay unconverted with a note.
- Arabic presentation forms and shared Persian letter variants (`U+06CC`, `U+06BE`, `U+06A9` when no Persian/Urdu-only letters appear on the page) map to searchable Arabic base letters.
- Words split by layout spaces are rejoined linearly against plain-mode text (up to `12` Arabic pieces and `8` LTR pieces).

What PDF reading order promises, and what it does not:

- Arabic words and sentences come out in reading order; Latin words and their numbers come out in
  the left-to-right order shown on the page.
- Runs of spaces collapse to a single space (runs of three or more spaces are **not** converted to
  tabs because font width quirks produce wide space runs inside ordinary phrases). PDF table
  columns are not marked; cells in a row are separated by one space, rightmost cell first on an RTL
  page.
- Three ambiguities cannot be known from page glyphs alone: (a) a Latin word beside a number
  (`5 GB` is drawn `GB 5` and comes out `GB 5`); (b) a number at the start of a continuation line
  of a paragraph; (c) slash-separated dates in a Word file printed through a virtual printer whose
  metadata does not contain `Word`.

- Keyed by `(attachment_id, size)` (or message id, index, name, and size when Exchange omits `attachment_id`).

### Worker limits, isolation, and hostile-input bounds

Document formats (`pdf`, `docx`, `xlsx`, `pptx`, `eml`, `message`, `html`) run inside
`python -m ewsmcp.extract_child` (`ewsmcp/extract_worker.py`, `ewsmcp/extract_child.py`,
`ewsmcp/extract.py`):

| limit / control | constant / setting | value | behaviour |
|---|---|---|---|
| Attachment size ceiling | `EWS_MAX_ATTACHMENT_MB` (`DEFAULT_MAX_ATTACHMENT_BYTES`) | `25` MB default (`1..50` MB; `26,214,400` bytes) | Checked against declared `size` before download and delivered byte count after download (`validation`). |
| Max concurrent workers | `EXTRACT_MAX_CONCURRENT` | `2` | Enforced via an `asyncio` semaphore; cancelling a call kills its child tree immediately and holds the semaphore slot until supervisor cleanup completes. |
| Hard wall-clock deadline | `EXTRACT_TIMEOUT_SECONDS` | `20.0` s | Parent kills the worker tree on timeout (Win32 Job Object with kill-on-close on Windows; `start_new_session=True` + process-group `SIGKILL` on POSIX). |
| Soft unit deadline | `EXTRACT_SOFT_DEADLINE_RATIO` | `0.75` (`15.0` s) | Checked between pages, sheets, slides, Word blocks, and MIME parts after unit 1; stops cleanly with `partial: true` and a cut note. |
| Worker memory ceiling | `EXTRACT_MEMORY_LIMIT_MB` (`DEFAULT_MEMORY_LIMIT_MB`) | `1,024` MB | Self-applied by the child before reading `stdin` (Win32 Job Object on Windows; `RLIMIT_AS` on Linux). Where unsupported, the child proceeds and `get_server_status.document_memory_ceiling` reports `enforced: false` with a note. |
| Worker stdout cap | `EXTRACT_MAX_OUTPUT_BYTES` | `25,165,824` (`24` MiB) | Overflow kills the child and fails with `validation`. |
| Extracted text ceiling | `MAX_EXTRACTED_CHARS` | `5,000,000` chars | Stops assembly with `partial: true` + cut note; lone surrogates replaced with `U+FFFD`. |
| Child JSON validation | `MAX_CHILD_NOTES` / `MAX_CHILD_UNIT_COUNT` / `MAX_CHILD_LOADED_MODULES` | `50` / `1,000,000` / `5,000` | Strict allow-listed keys (`_ALLOWED_OK_KEYS`, `_ALLOWED_ERR_KEYS`), fixed `extracted_from` set, bounded ints; diagnostic fields are never trusted for server decisions. |
| ZIP archive members | `MAX_ARCHIVE_MEMBERS` | `2,000` members | Checked before reading any member; only stored and deflated compression allowed; encrypted members fail with `validation`; `.bin` and `vbaProject` parts are never read (a document part that points at one is refused). |
| ZIP & XML byte/depth caps | `MAX_MEMBER_BYTES` / `MAX_XML_PART_BYTES` / `MAX_ARCHIVE_TOTAL_BYTES` / `MAX_XML_DEPTH` | `30` MiB (`31,457,280`) / `20` MiB (`20,971,520`) / `100` MiB (`104,857,600`) / `256` levels | Decompressed in `65,536`-byte chunks (`_READ_CHUNK_BYTES`); `defusedxml` forbids DTDs, entities, and external references. |
| Error & echo length caps | `MAX_ERROR_MESSAGE_CHARS` / `MAX_ECHOED_TEXT_CHARS` | `300` / `80` chars | Malformed, truncated, or mislabelled files fail closed with `validation`; `validation` results do not count toward the circuit-breaker failure counter (`ctx._circuit_failures`, incremented only for `upstream_unavailable`, `upstream_error`, and `throttled`). |
| Linux non-dumpable server | `EWS_KEEP_DUMPABLE` (`PR_SET_DUMPABLE`) | `False` default | On Linux, marks the server process non-dumpable (`prctl(PR_SET_DUMPABLE, 0)`) before the first child starts so same-UID processes cannot read `/proc/<pid>/environ` or server memory; set `EWS_KEEP_DUMPABLE=true` only when debugging requires core dumps or `ptrace`. |

Isolation details and security boundary:

- **Imports and scrubbed environment**: Each child imports only the Python stdlib, `defusedxml`, and
  `ewsmcp` extraction modules (`pypdf` is imported only for PDFs; `exchangelib`, `mcp`, `requests`,
  and server/gateway/tool modules are never loaded). Its environment strips `USERNAME`, `EWS_*`,
  `MCP_*`, `SEND_*`, and any `*PASSWORD*`, `*SECRET*`, `*TOKEN*`, or `*KEY*` variable; `PATH` is
  reduced to the Python interpreter directory (plus Windows `System32` / base prefix when required);
  `stderr` goes to `DEVNULL`; and its fresh empty temporary working directory is deleted with retry
  on exit.
- **Worker failure vs unavailable**: A child whose first unit hangs past `20` s, exceeds memory,
  fails to set its memory ceiling on Windows/Linux, exits non-zero, or emits invalid JSON fails
  closed with `validation` (`"the document could not be read within the time and memory limits"`,
  `WORKER_LIMIT_ERROR_MESSAGE`). If the server cannot create the temp directory or start the worker
  process, `get_attachment` returns `internal` (`"Document reader is unavailable..."`,
  `WORKER_UNAVAILABLE_ERROR_MESSAGE`); `internal` results do not count toward the circuit-breaker
  failure counter (`ctx._circuit_failures`).
- **What the worker protects against, and what it does not**: The worker contains **time, memory,
  and parser crashes** so a malformed file cannot stall or crash the MCP server. It is **not** an OS
  user or filesystem sandbox: code inside a compromised parser runs as the server's OS user account
  and can access files open to that account.

### Saving to disk, S/MIME, and `.msg`

- **Saving (`mode="save"` and `get_message(format="eml")`)**: Writes raw attachment or `.eml` bytes
  exclusively under `DATA_DIR/attachments`; `get_message(format="eml")` enforces
  `EWS_MAX_ATTACHMENT_MB`, `get_attachment(mode="save")` does not. Filenames prefix `_` onto
  reserved Windows device stems, cap the stem at `200` UTF-8 bytes (`_MAX_STEM_UTF8_BYTES`), and
  add `-2`, `-3`, … rather than overwriting existing files.
  `get_message(format="eml")` returns `saved_path` and `size_bytes`, and an `.eml` exported from
  Sent Items may retain its `Bcc` header because it is written as stored in the mailbox. If
  `DATA_DIR/attachments` cannot be written, both tools return `internal`, which does not count
  toward the circuit-breaker failure counter (`ctx._circuit_failures`).
- **S/MIME (`.p7m`, `.p7s`)**: `smime.p7m` (`application/pkcs7-mime`) attachments up to `5` MiB
  (`_SMIME_SNIFF_MAX_BYTES = 5,242,880`; larger files stay `mode: "info"` in `info`/`auto`) are
  sniffed by DER OID and reported as `smime_type: "signed"` or `"enveloped"`. `signed` is **not**
  encrypted (`auto` and `text` decode up to `20,000` UTF-8 chars with a `hint` explaining `\ufffd`
  replacement chars around certificate/signature bytes); `enveloped` **is** encrypted (`auto` stays
  `mode: "info"` because decryption requires the recipient's private key). Detached `.p7s`
  (`application/pkcs7-signature`) signatures return `mode: "info"` in `info`/`auto` without setting
  `smime_type` (`get_message` sniffs `.p7m` `<= 5` MiB for `smime_type`, whereas batch
  `get_messages` reports `smime_type: "candidate"` from metadata without downloading bytes).
- **Outlook `.msg`**: `.msg` files (`application/vnd.ms-outlook`) are not decoded as text; both
  `mode="auto"` and `mode="text"` return `mode: "info"` with a `note` and `hint` to save the file
  with `mode='save'` and open it externally.

`get_attachment` arguments (Word document read in memory):

```json
{
  "message_id": "m1",
  "attachment": "0",
  "mode": "text"
}
```

Result:

```json

  "ok": true,
  "name": "status-report.docx",
  "size_bytes": 832,
  "content_type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  "mode": "text",
  "extracted_from": "docx",
  "text": "Status report\nAll three milestones are on schedule.\nNext review: 14 March.",
  "offset": 0,

```

## Inbox rules

`list_rules` (`read` tier, stamped `source: "live"`) lists server-side Exchange Inbox rules.
`save_rule` and `delete_rule` (`draft` tier, both class `write` so a `draft`-tier caller can undo
its own rule) create, wholesale-replace, or delete rules, and **every** call to either tool is
two-phase confirmed. Remember one Exchange caveat: **any** EWS rule write (`UpdateInboxRules`) sends
`RemoveOutlookRuleBlob=true`, which permanently deletes client-side rules that only Outlook can
store (such as client-side send rules) and can drop rules that were disabled in the Outlook desktop
UI.

### Outlook-only rules (`outlook_only_rules`)

`list_rules` reads `OutlookRuleBlobExists` from Exchange and reports top-level `outlook_only_rules`
(`true|false|null`). Both `save_rule` and `delete_rule` add an explicit warning in their phase-1
`preview.warnings` whenever `outlook_only_rules` is `true` or `null` (`save_rule` also warns when a
rule has no `conditions` and therefore matches every incoming message).

### Writable rule fields and folder verification (`save_rule`)

| part | allowed values and defaults | refused with `validation` |
|---|---|---|
| `name`, `priority`, `enabled`, `rule_id` | `name`: `1..255` plain chars (`MAX_RULE_STR_LEN`); `priority`: `1..2,147,483,647` (`MAX_RULE_PRIORITY`); `enabled` boolean; `rule_id` selects replace mode (`preview.changes` vs `preview.current`). | Replacing a rule with `editable: false` (refused so unsupported fields are never silently dropped; unknown `rule_id` fails with `not_found`). |
| `actions` (`WRITABLE_ACTION_KEYS`, `>= 1` required) | `save_rule` builds `Actions` strictly from six mailbox-internal fields: `move_to_folder`, `copy_to_folder`, `assign_categories` (`1..255` chars per category), `mark_as_read` (`true`), `mark_importance` (`low\|normal\|high`), `stop_processing_rules` (`true`). | Actions that send, forward, redirect, auto-reply, send SMS alerts, or delete mail; `move_to_folder` or `copy_to_folder` targeting Deleted Items, Junk Email, or any subfolder below them. |
| Target folder verification (both phases) | Matches Deleted Items and Junk Email by `DeletedItems` / `JunkEmail` class, `DISTINGUISHED_FOLDER_ID`, `WELL_KNOWN` name, and raw id; walks live `parent_folder_id` ancestry up to `msg_folder_root` (bounded to `25` levels); always writes a concrete `FolderId`. | Fails closed if Deleted Items or Junk Email ids cannot be determined (unless Exchange reports `ErrorFolderNotFound`) or if folder ancestry cannot reach `msg_folder_root`. |
| `conditions` (optional) | `from_addresses`, `sent_to_addresses`, `subject_contains`, `body_contains`, `subject_or_body_contains`, `sender_contains`, `recipient_contains` (`<= 255` chars per string), `importance` (`low\|normal\|high`), and booleans (`true` only): `has_attachments`, `sent_to_me`, `sent_cc_me`, `sent_only_to_me`, `sent_to_or_cc_me`, `not_sent_to_me`. | Passing `false` for a boolean condition (omit instead), any unlisted condition, or rule exceptions. |

#### `name`, `priority`, `enabled`, `rule_id`

- `name` (`1..255` plain chars, `MAX_RULE_STR_LEN`, no control/surrogate chars) refuses duplicate names on create.
- `priority` (`1..2,147,483,647`, `MAX_RULE_PRIORITY`) defaults to `1` on create and preserves the current value when omitted on replace; `enabled` defaults to `true` on create and preserves the current value when omitted on replace.
- On replace (`rule_id` supplied), `preview.changes` lists which of `name`, `priority`, `enabled`, `conditions`, and `actions` differ from `preview.current`.

### Read-only rules, token binding, and execution

| behaviour | details |
|---|---|
| `list_rules` & `editable: false` | Emits `r`-alias ids, flags non-writable rules with `editable: false` and `unsupported`, and annotates mail-sending (`sends_mail: true`, `recipients`) and broken (`in_error: true`) rules. |
| Token binding & `_rules_lock` | Serialises `save_rule` and `delete_rule` under `_rules_lock`; binds the planned rule, target rule's SHA-256 XML fingerprint, raw folder ids, and `outlook_only_rules`. |
| Direct EWS calls & `verified: false` | Calls `CreateInboxRule`, `SetInboxRule`, and `DeleteInboxRule` directly; if read-back fails after write, `save_rule` returns `ok: true` and `verified: false`. |
| Deleting `editable: false` & disabled rules | `delete_rule` deletes `editable: false` rules and neutralises disabled rules hit by `ErrorItemNotFound` via `SetInboxRule` before deleting. |

#### `list_rules` & `editable: false`

- Never mints `r` aliases for nonexistent ids and resolves each distinct target folder at most once per call.
- Marks `editable: false` and lists field names in `unsupported` when a rule uses a non-writable action, an exception, a condition outside the 14 writable keys, a present-but-unreadable XML element, a move/copy target without a readable folder id or resolvable label, or `is_not_supported`.
- Adds `sends_mail: true` and `recipients` on rules that send/forward mail, and `in_error: true` when Exchange flags a broken rule.

#### Token binding & `_rules_lock`

- `save_rule` and `delete_rule` are serialised in-process under `_rules_lock` (keeping standard dispatcher audit records).
- Their `confirm_token` binds the planned rule (including raw target folder ids), the replaced/deleted rule (including a SHA-256 fingerprint of its serialised XML), and `outlook_only_rules`; changes to unrelated rules do not invalidate the token.

#### Direct EWS calls & `verified: false`

- Writes call `CreateInboxRule`, `SetInboxRule`, and `DeleteInboxRule` directly and keep read-back separate.
- If the Exchange write succeeded and read-back failed, `save_rule` returns `ok: true`, `verified: false`, the planned rule (`id: null` on create), and a `note` instructing the caller to run `list_rules`.

#### Deleting `editable: false` & disabled rules

- `delete_rule` can delete rules with `editable: false`.
- When `delete_rule` targets a disabled rule and Exchange returns `ErrorItemNotFound`, it first neutralises the rule via `SetInboxRule` into an enabled no-match rule (a fresh `48`-character random `contains_subject_strings` token and `stop_processing_rules` only) and then deletes it.

## Intentionally dropped vs v3

The 30 legacy tools marked `dropped, see below` above were removed deliberately because they either
weaken the safety boundary or belong in the calling assistant rather than a mailbox data-plane
server:

| dropped v3 tools | reason and 4.5 alternative |
|---|---|
| `send_email`, `reply_email`, `forward_email` | One-shot send tools removed. Ordinary mail leaves the mailbox only through `create_draft` followed by `send_draft`. |
| `copy_email` | Folder-to-folder message copy removed; use `move_messages` or an Inbox rule `copy_to_folder` action. |
| `manage_folder` | Mail folder mutations — create, rename, move, and delete folders — removed. |
| `create_contact`, `update_contact`, `delete_contact` | Contacts folder mutations removed; `find_people` and `get_contact` remain read-only. |
| `create_task`, `delete_task` | Task creation and deletion removed; `list_tasks` and `update_task` remain. |
| `apply_oof_policy`, `configure_oof_policy`, `get_oof_policy` | Server-side OOF template and forwarding policy store removed; use native Exchange `get_oof_settings`, `set_oof`, and `save_rule`. |
| `evaluate_rules_on_message`, `rule_simulate` | Local memory-store rule evaluation and dry-run simulation removed; `list_rules`, `save_rule` (with phase-1 preview), and `delete_rule` manage native Exchange server-side Inbox rules. |
| `approve`, `execute_approved_action`, `list_pending_approvals`, `reject`, `submit_for_approval` | Stateful server-side approval queue removed; replaced by stateless content-bound two-phase `confirm_token` confirmation in the dispatcher. |
| `list_commitments`, `resolve_commitment`, `track_commitment` | Server-side commitment ledger removed; `waiting_on` answers unanswered sent threads from the local mirror. |
| `memory_delete`, `memory_get`, `memory_list`, `memory_set` | Server-side agent key-value memory store removed; state and notes belong in the calling assistant. |
| `analyze_contacts`, `get_voice_profile`, `prepare_meeting` | Server-side "agent secretary" tools removed; the caller is already a language model — see [SKILL.md](../../examples/skills/exchange-assistant/SKILL.md) (`examples/skills/exchange-assistant/`) for the client-side skill pattern. |

Three non-tool v3 features were also removed:

- **Per-call mailbox impersonation (`target_mailbox`)**: One 4.5 server instance serves one mailbox.
- **OAuth2 / MSAL flows**: 4.5 targets Exchange EWS with auto-negotiated or forced `basic`, `ntlm`,
  or `digest` authentication; a Graph or OAuth backend belongs in a separate gateway.
- **Inline raw MIME bytes in tool responses**: `get_message(format="eml")` writes the `.eml` file
  under `DATA_DIR/attachments` instead and returns `saved_path` and `size_bytes`.
